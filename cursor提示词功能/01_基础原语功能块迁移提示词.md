# 基础原语功能块迁移提示词

> 用途：迁移最基础、可复用的 PLC 原语功能块。  
> 典型对象：`TON`、`TOF`、`TP`、`R_TRIG`、`F_TRIG`、`SR`、`RS`。  
> 建议：先贴 `00_项目级总前置提示词.md`，再贴本提示词，最后贴原始材料。

```text
请在严格遵守“项目级总前置提示词”的前提下，将下面这个基础原语功能块迁移为 Python。

当前任务目标：
迁移的是 PLC 基础原语功能块，而不是业务功能块。
请优先保证语义正确、周期行为正确、状态保持正确。

要求：

1. 将该功能块实现为 Python 类。
2. 接口优先采用 step(dt, ...) 或 update(dt, ...)。
3. 必须体现 PLC 扫描周期语义，而不是普通脚本语义。
4. 对于定时器类功能块，必须基于 dt 进行时间累积。
5. 对于触发器类功能块，必须依赖上一周期状态。
6. 对于锁存类功能块，必须正确保持状态。
7. 输出的代码要尽量简洁、清晰、可复用。
8. 不要引入无关框架。
9. 不要擅自改变该原语功能块的标准行为。
10. 如发现 IEC / CODESYS 语义存在不同实现习惯，请明确说明你采用的假设。

请按以下结构输出：

1. 你对该基础原语功能块语义的理解
2. Python 实现
3. step(dt, ...) 的最小调用示例
4. 与 PLC 标准语义的一致性说明
5. 风险点、假设和待确认项
6. 如有必要，给出一个最小测试示例

原始内容如下：
[在这里粘贴 TON / TOF / TP / R_TRIG / F_TRIG / SR / RS 的定义、说明或 ST 代码]
```

---

## 推荐使用顺序

建议优先按下面顺序迁移：

1. TON
2. TOF
3. TP
4. R_TRIG
5. F_TRIG
6. SR
7. RS

---

## 输入材料建议

建议尽量提供：

- 原始 ST 代码或功能说明
- 输入输出定义
- 期望行为说明
- 如果存在，IEC / CODESYS 具体实现差异说明
